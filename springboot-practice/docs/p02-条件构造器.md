# p02 条件构造器 Wrapper

> 先看：[MyBatis-Plus 文档](https://baomidou.com/) “条件构造器”（重点看 eq、like、between、in、orderBy、and、or、select、groupBy、last，以及 LambdaQueryWrapper / LambdaUpdateWrapper）
> 练习：`src/main/java/com/learn/web/p02_wrapper/DishWrapperService.java`　判题：`mvn test -Dtest=P02WrapperTest`

## 速记

```java
LambdaQueryWrapper<Dish> lqw = Wrappers.lambdaQuery();
lqw.like(StringUtils.hasText(name), Dish::getName, name)          // 第一个参数为 false 时，这个条件不拼
   .eq(categoryId != null, Dish::getCategoryId, categoryId)
   .between(Dish::getPrice, 10, 30)
   .in(Dish::getId, ids)
   .orderByAsc(Dish::getPrice).orderByAsc(Dish::getId);
List<Dish> list = dishMapper.selectList(lqw);
```

| 方法 | SQL | 方法 | SQL |
|---|---|---|---|
| `eq` / `ne` | `=` / `<>` | `like` / `likeLeft` / `likeRight` | `%x%` / `%x` / `x%` |
| `gt` / `ge` | `>` / `>=` | `in` / `notIn` | `IN (...)` |
| `lt` / `le` | `<` / `<=` | `isNull` / `isNotNull` | `IS NULL` |
| `between` | `BETWEEN a AND b` | `orderByAsc` / `orderByDesc` | `ORDER BY` |
| `select(列...)` | 只查这些列 | `groupBy` | `GROUP BY` |
| `and(w -> ...)` | `AND ( ... )` | `or()` | `OR` |
| `last("...")` | 原样拼到最后（有注入风险） | `exists` / `apply` | 原生 SQL 片段 |

**为什么用 `Dish::getName` 而不是字符串 `"name"`**：写错字段名编译就报错，重构改字段名时也会一起改。
分组统计这类 Lambda 不好表达的，才用普通的 `QueryWrapper` 写列名字符串。

## 对比 b02 的 XML

b02 的 `<where><if test="categoryId != null">AND category_id = #{categoryId}</if></where>`
就是这里的 `.eq(categoryId != null, Dish::getCategoryId, categoryId)`。
RuoYi-Vue-Plus 每个 ServiceImpl 里都有一个 `buildQueryWrapper(bo)` 方法，全是这种写法（p03 练习 3.5 你会写一个）。

## and / or 的括号（练习 2.2，高频 bug）

```java
// 错：status = 1 AND name LIKE '%辣%' OR description LIKE '%辣%'   → 停售的菜只要描述里有“辣”也会查出来
lqw.eq(Dish::getStatus, 1).like(Dish::getName, kw).or().like(Dish::getDescription, kw);

// 对：status = 1 AND (name LIKE '%辣%' OR description LIKE '%辣%')
lqw.eq(Dish::getStatus, 1).and(w -> w.like(Dish::getName, kw).or().like(Dish::getDescription, kw));
```

## 更新

```java
dishMapper.update(Wrappers.<Dish>lambdaUpdate()
        .set(Dish::getStatus, 0)                       // SET status = 0
        .setIncrBy(Dish::getPrice, new BigDecimal("1")) // SET price = price + 1
        .eq(Dish::getCategoryId, 2));                  // WHERE category_id = 2
```

## 常见坑

1. 值是 null 时条件**不会**自动跳过，照样拼进 SQL，查出来的结果就不对了；要跳过必须用带 boolean 参数的重载。
2. `StringUtils.hasText` 是 Spring 的（`org.springframework.util.StringUtils`），RuoYi 里用的是自己封装的 `StringUtils.isNotBlank`，作用一样。
3. 用 `update(entity, wrapper)` 时 entity 里不为 null 的字段也会被 SET 进去，不需要就传 null 或用只有 wrapper 的 `update(wrapper)`。
