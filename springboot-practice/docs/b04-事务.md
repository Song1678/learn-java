# b04 事务 @Transactional

> 先看：mysql-practice 的 m06（事务）和 m08 的 `OrderSubmitService`（手动事务）；黑马《JavaWeb 开发教程》“事务管理”（@Transactional、rollbackFor、propagation）
> 练习：`src/main/java/com/learn/web/b04_tx/`　判题：`mvn test -Dtest=B04TransactionTest`

## 从手动事务到 @Transactional

```java
// m08：手动
conn.setAutoCommit(false);
try {
    insertOrder(...); insertDetails(...); clearCart(...);
    conn.commit();
} catch (Exception e) {
    conn.rollback();
    throw e;
}

// Spring：声明式
@Transactional(rollbackFor = Exception.class)
public TxOrder submit(...) {
    insertOrder(...); insertDetails(...); clearCart(...);
}
```

Spring 给 `OrderTxService` 生成了一个**代理对象**注入到别人那里。别人调用 `submit` 时，先进代理：
开启事务 → 调用你的 `submit` → 正常返回就提交，抛出异常就回滚。

## 回滚规则

| 方法里发生了什么 | 默认 `@Transactional` | `@Transactional(rollbackFor = Exception.class)` |
|---|---|---|
| 抛出 RuntimeException（比如 ServiceException） | 回滚 | 回滚 |
| 抛出受检异常（IOException、SQLException） | **提交！** | 回滚 |
| 异常被 catch 住、没有再抛出 | **提交！** | **提交！** |

## @Transactional 失效的三个经典场景（练习 4.4 ~ 4.6）

1. **受检异常**：默认不回滚 → 加 `rollbackFor = Exception.class`（RuoYi-Vue-Plus 里几乎都这么写）
2. **异常被吞**：catch 之后只打日志，Spring 不知道出错了 → catch 之后要重新 throw
3. **自调用**：同一个类里 `this.doImport()`，`this` 不是代理对象，注解不生效 → 把 `@Transactional` 放到外部调用的那个方法上

还有一些：方法不是 public、类没有被 Spring 管理（自己 new 的）、数据库表不是 InnoDB（MyISAM 不支持事务）。

## 常见坑

1. 测试里看到“订单要回滚”但数据还在 → 检查方法上有没有 `@Transactional`，以及异常有没有真的抛出方法。
2. 事务方法里尽量不要做慢操作（调用第三方接口、发短信），事务时间越长，锁住的数据越多。
3. `propagation`（传播行为）先知道默认是 `REQUIRED`：“有事务就加入，没有就新建”，其他的用到再学。
