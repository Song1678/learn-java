# x01 综合项目：外卖后台管理接口

> 先做完：w01 ~ w04、p01 ~ p03（**分页插件和自动填充是 p03 写的，x01 依赖它们**）；b04（事务）
> 练习：`src/main/java/com/learn/web/x01_takeout/` + `src/main/resources/mapper/x01/ReportMapper.xml`
> 判题：`mvn test -Dtest='X01*'`（分类 `X01CategoryApiTest`、菜品 `X01DishApiTest`、统计 `X01ReportApiTest`）

## 目标

把前面学的全部串起来，写一套**和 RuoYi-Vue-Plus 代码结构一样**的后台接口：苍穹外卖管理端的分类管理、菜品管理、数据统计。
做完以后打开 RuoYi-Vue-Plus 的任何一个业务模块，你都能看懂它的每一层在干什么。

## 项目结构（和 RuoYi-Vue-Plus 一一对应）

```
x01_takeout/
├── controller/      CategoryController、DishController、ReportController   ← 练习：加注解 + 调 Service
├── service/         ICategoryService、IDishService、IReportService         （接口，已写好）
│   └── impl/        CategoryServiceImpl、DishServiceImpl、ReportServiceImpl  ← 练习：业务逻辑
├── mapper/          XxxMapper extends BaseMapper（已写好）、ReportMapper      ← 练习：ReportMapper.xml
├── domain/          Category、Dish、DishFlavor、Setmeal、SetmealDish         （实体，对应表，已写好）
│   ├── bo/          CategoryBo、DishBo                                        （接收参数 + 校验注解，已写好）
│   └── vo/          DishVo、TurnoverReportVo、SalesTop10ReportVo ...           （返回给前端，已写好）
└── handler/         GlobalExceptionHandler                                    （已写好，w04 的答案）
```

| 本项目 | RuoYi-Vue-Plus（以“通知公告”模块为例） |
|---|---|
| `CategoryController` | `SysNoticeController`（多了 `@SaCheckPermission` 权限注解、`@Log` 操作日志） |
| `ICategoryService` / `CategoryServiceImpl` | `ISysNoticeService` / `SysNoticeServiceImpl` |
| `CategoryMapper extends BaseMapper<Category>` | `SysNoticeMapper extends BaseMapperPlus<SysNotice, SysNoticeVo>` |
| `Category` / `CategoryBo` / `Category`（直接返回实体） | `SysNotice` / `SysNoticeBo` / `SysNoticeVo` |
| 手动把 Bo 的字段 set 到实体 | `MapstructUtils.convert(bo, SysNotice.class)` |
| `queryPageList`、`queryById`、`insertByBo`、`updateByBo` | 方法名完全一样（代码生成器就是这么生成的） |

## 接口文档

所有接口返回 `R`（`{"code": 200, "msg": "操作成功", "data": ...}`），列表接口返回 `TableDataInfo`（`{"code": 200, "total": 20, "rows": [...]}`）。
业务错误返回 `code=500` + 错误信息；参数校验失败返回 `code=400` + 校验信息（GlobalExceptionHandler 已经写好）。

### 分类管理 `/admin/category`

| 题 | 接口 | 参数 | 返回 | 业务规则 |
|---|---|---|---|---|
| x.1 | `GET /list` | 查询参数：name（模糊）、type、pageNum、pageSize | `TableDataInfo<Category>` | 按 sort、id 升序 |
| x.1 | `GET /listByType` | `type`（必填） | `R<List<Category>>` | 只要启用的，按 sort、id 升序 |
| x.1 | `GET /{id}` | | `R<Category>` | 不存在："分类不存在" |
| x.2 | `POST` | JSON：CategoryBo（type、name、sort），新增分组校验 | `R<Long>` 新 id | 默认启用；重名："分类名称已存在" |
| x.2 | `PUT` | JSON：CategoryBo（id、type、name、sort），修改分组校验 | `R<Void>` | 不存在 / 和别的分类重名 |
| x.3 | `DELETE /{id}` | | `R<Void>` | 有菜品："当前分类关联了菜品，不能删除"；有套餐："当前分类关联了套餐，不能删除" |
| x.3 | `PUT /{id}/status/{status}` | | `R<Void>` | status 只能 0/1："状态不合法" |

### 菜品管理 `/admin/dish`

| 题 | 接口 | 参数 | 返回 | 业务规则 |
|---|---|---|---|---|
| x.4 | `GET /list` | 查询参数：name（模糊）、categoryId、status、pageNum、pageSize | `TableDataInfo<DishVo>` | 按 id 升序；要带 categoryName；分类名只查一次库 |
| x.5 | `GET /{id}` | | `R<DishVo>` | 带 categoryName 和 flavors；不存在："菜品不存在" |
| x.6 | `POST` | JSON：DishBo（含 flavors 列表），新增分组校验 | `R<Long>` 新 id | 默认停售；分类必须存在且是菜品分类；重名；**事务** |
| x.7 | `PUT` | JSON：DishBo（含 id、flavors），修改分组校验 | `R<Void>` | 口味整体替换（先删后插）；**事务** |
| x.8 | `DELETE /{ids}` | 例如 `/10,18` | `R<Void>` | 起售中 / 被套餐包含的不能删；连口味一起删；**事务** |
| x.8 | `PUT /{id}/status/{status}` | | `R<Void>` | 停售时，包含它的套餐也停售；**事务** |

### 数据统计 `/admin/report`

| 题 | 接口 | 参数 | 返回 |
|---|---|---|---|
| x.9 + x.10 | `GET /turnoverStatistics` | begin、end（yyyy-MM-dd） | `R<TurnoverReportVo>`：`{"dateList": "2024-05-01,...", "turnoverList": "150.00,..."}`，没订单的日期是 0.00 |
| x.9 + x.10 | `GET /top10` | begin、end | `R<SalesTop10ReportVo>`：`{"nameList": "米饭,宫保鸡丁,...", "numberList": "18,6,..."}` |

（返回逗号分隔字符串是苍穹外卖前端 ECharts 图表要求的格式。）

## 建议顺序

1. **分类**（x.1 ~ x.3）：先写 `CategoryServiceImpl`，再写 `CategoryController`，每写完一个接口就启动项目用 Apifox 调一下，再跑 `X01CategoryApiTest`
2. **菜品**（x.4 ~ x.8）：最难的部分，注意事务和“分类名称只查一次”
3. **统计**（x.9 ~ x.10）：先写 XML 里的 SQL（和 b03 几乎一样），再写 Service 拼字符串

每个 ServiceImpl 的注释里写了详细规则和错误信息，测试会逐字检查。
