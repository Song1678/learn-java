# b03 结果映射与多表查询

> 先看：mysql-practice 的 m04（多表查询）和 m07（统计报表）；[MyBatis 中文文档](https://mybatis.org/mybatis-3/zh_CN/index.html) “XML 映射器 → 结果映射”
> 练习：`src/main/resources/mapper/b03/*.xml` + `src/main/java/com/learn/web/b03_resultmap/ReportService.java`
> 判题：`mvn test -Dtest=B03ResultMapTest`

## 三种情况，三种写法

**1. 多表查询，但结果是“一行对一个对象”** —— 起别名 + resultType 就够了：

```xml
<select id="selectWithCategory" resultType="...DishVO">
    SELECT d.id, d.name, c.name AS category_name ...   <!-- category_name → categoryName（驼峰映射） -->
    FROM dish d JOIN category c ON c.id = d.category_id
</select>
```

**2. 一对多：一个菜品有多个口味** —— JOIN 出来是多行，要“合并”成一个对象 + 一个列表，用 resultMap：

```
SQL 结果：                                   想要的对象：
id | name   | flavor_name | flavor_value     DishVO{id=3, name=水煮鱼,
3  | 水煮鱼  | 辣度        | 微辣,中辣,重辣        flavors=[{辣度, 微辣,中辣,重辣},
3  | 水煮鱼  | 忌口        | 不要香菜                       {忌口, 不要香菜}]}
```

```xml
<resultMap id="dishDetailMap" type="...DishVO">
    <id column="id" property="id"/>                 <!-- 关键：MyBatis 用 id 判断哪些行是同一个菜品 -->
    <result column="name" property="name"/>
    <collection property="flavors" ofType="...FlavorVO">   <!-- 一对多用 collection，ofType 是元素类型 -->
        <result column="flavor_name" property="name"/>
        <result column="flavor_value" property="value"/>
    </collection>
</resultMap>
<select id="selectDetail" resultMap="dishDetailMap"> ... </select>   <!-- 注意这里是 resultMap 不是 resultType -->
```

（一对一用 `<association>`，比如订单关联一个地址，用法类似。）

**3. 统计查询** —— 结果是 DTO：`SELECT DATE(order_time) AS order_date, SUM(amount) AS turnover ... GROUP BY ...`

## “补 0”放在 SQL 里还是 Java 里

mysql-practice m07 第 1 题你用 SQL（递归 CTE 生成日期序列）补 0。实际项目里更常见的是：
SQL 只查有数据的日期，Java 里从开始日期循环到结束日期，Map 里没有的补 0（练习 3.6）。两种都要会。

## 常见坑

1. 一对多查询返回了多个重复的菜品对象、每个只有一个口味 → resultMap 里少了 `<id>`。
2. 菜品名变成了口味名 → 两张表都有 `name` 列，没给口味的列起别名。
3. 没有口味的菜品查不出来 → 用了 JOIN，应该用 LEFT JOIN。
4. 时间范围用“左闭右开” `>= begin AND < end`，不要用 `BETWEEN '2024-05-01' AND '2024-05-08'` —— 那样 05-08 当天 0 点以后的数据都漏了。
5. `Collectors.toMap` 遇到重复 key 会抛异常；这里按日期分组过了，不会重复。
