## RESTful 风格

同一个资源（菜品）用同一个 URL，**用请求方式区分做什么**：

| 操作 | 请求 | 注解 | 参数从哪来 |
|---|---|---|---|
| 查一个 | `GET /w02/dishes/1` | `@GetMapping("/{id}")` | `@PathVariable Long id` |
| 条件查询 | `GET /w02/dishes?name=鸡&status=1` | `@GetMapping` | `DishQuery query`（不加注解） |
| 分页 | `GET /w02/dishes/page?pageNum=1&pageSize=10` | `@GetMapping("/page")` | `@RequestParam(defaultValue = "1") int pageNum` |
| 新增 | `POST /w02/dishes` + JSON | `@PostMapping` | `@RequestBody DishBo bo` |
| 修改 | `PUT /w02/dishes` + JSON | `@PutMapping` | `@RequestBody DishBo bo` |
| 删除 | `DELETE /w02/dishes/1,2,3` | `@DeleteMapping("/{ids}")` | `@PathVariable List<Long> ids` |

RuoYi-Vue-Plus 的每个 Controller 都是这个套路，代码生成器生成的就是这 6 个方法。

## 几种接收参数的方式

```java
// 1. 对象接收查询参数：?name=鸡&categoryId=1 会调用 query.setName("鸡")、query.setCategoryId(1L)
@GetMapping
public R<List<Dish>> list(DishQuery query) { ... }

// 2. JSON 请求体：Content-Type: application/json，{"name": "小笼包", "price": 18.5}
@PostMapping
public R<Long> add(@RequestBody DishBo bo) { ... }

// 3. 路径里的逗号分隔列表
@DeleteMapping("/{ids}")
public R<Integer> remove(@PathVariable List<Long> ids) { ... }

// 4. 日期：URL 里都是字符串，要告诉 Spring 格式
public R<...> dates(@RequestParam @DateTimeFormat(pattern = "yyyy-MM-dd") LocalDate begin, ...)

// 5. 请求头
public R<String> token(@RequestHeader(value = "Authorization", required = false) String token)

// 6. 不想写类时，用 Map 接收任意 JSON
public R<...> keys(@RequestBody Map<String, Object> body)
```

**记住**：`@RequestBody` 只能有一个（请求体只有一个），而且只能接收 JSON；查询参数（问号后面的）不能用 `@RequestBody` 接收。

## 返回日期的格式

```java
@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")
private LocalDateTime createTime;     // 默认是 "2024-04-05T10:10:00"，加注解后 "2024-04-05 10:10:00"
```

`@DateTimeFormat` 管**接收**（字符串 → 日期），`@JsonFormat` 管 JSON **输出**（日期 → 字符串），别搞混。

## 常见坑

1. POST 的 JSON 没加 `@RequestBody` → 参数全是 null（不报错！），测试会提示“名称是 null”。
2. Apifox 里 Body 选成了 form-data，却用 `@RequestBody` 接收 → 415 Unsupported Media Type。
3. `/page` 和 `/{id}` 会不会冲突？不会，Spring 优先匹配写死的路径；但是如果 `/{id}` 收到 `abc`，转 Long 失败会返回 400。
4. JSON 里的字段名要和 Java 字段名一致（`categoryId`，不是 `category_id`）。
5. 接口返回的 JSON 里 Long 类型的 id 太大时，前端 JS 会丢精度（雪花 id 有 19 位）——RuoYi-Vue-Plus 专门配置了把 Long 转成字符串输出，以后会遇到。
