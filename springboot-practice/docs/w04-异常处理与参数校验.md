# w04 统一异常处理与参数校验

> 先看：回顾 ch09 的 `GlobalExceptionHandler`、ch05 的 `Validator`；黑马《JavaWeb 开发教程》“全局异常处理器”；
> 参考：RuoYi-Vue-Plus `ruoyi-common-web` 模块的 `GlobalExceptionHandler`
> 练习：`src/main/java/com/learn/web/w04_exception/`　判题：`mvn test -Dtest=W04ExceptionTest`

## 统一异常处理

```java
@RestControllerAdvice                     // 对所有 Controller 生效（本练习加了 basePackages 限制范围）
public class GlobalExceptionHandler {

    @ExceptionHandler(ServiceException.class)          // Controller 抛出 ServiceException 时调用这个方法
    public R<Void> handleServiceException(ServiceException e) {
        return R.fail(e.getCode(), e.getMessage());    // 返回值就是给前端的 JSON
    }

    @ExceptionHandler(Exception.class)                 // 兜底：其他所有异常
    public R<Void> handleException(Exception e) {
        log.error("系统异常", e);                       // 一定要记日志，否则线上出了 bug 无从查起
        return R.fail(500, "系统繁忙，请稍后再试");      // 不要把 e.getMessage() 返回给前端（可能暴露 SQL、表名）
    }
}
```

有了它，**Service 里遇到业务问题直接 throw**，Controller 里不用 try-catch，代码只写“正常流程”。

## 参数校验

```java
// 1. 在 Bo 的字段上声明规则
@NotBlank(message = "账号不能为空", groups = {AddGroup.class, EditGroup.class})
@Size(min = 4, max = 20, message = "账号长度必须在4到20之间", groups = {AddGroup.class, EditGroup.class})
private String username;

// 2. 在 Controller 参数上开启校验，并指定分组
@PostMapping
public R<Long> add(@Validated(AddGroup.class) @RequestBody EmployeeBo bo) { ... }

// 3. 直接校验方法参数：类上加 @Validated，参数上写约束
@Validated
@RestController
public class EmployeeController {
    @GetMapping("/{id}")
    public R<EmployeeBo> getById(@PathVariable @Min(value = 1, message = "id必须大于0") Long id) { ... }
}
```

| 注解 | 作用 | 注意 |
|---|---|---|
| `@NotNull` | 不能为 null | 任何类型 |
| `@NotBlank` | 不能为 null、空字符串、全空格 | 只用于字符串 |
| `@NotEmpty` | 不能为 null、长度不能为 0 | 字符串、集合 |
| `@Size(min, max)` | 长度范围 | null 算通过 |
| `@Min` / `@Max` / `@DecimalMin` | 数值范围 | null 算通过 |
| `@Pattern(regexp)` | 正则 | null 算通过 |
| `@Email` | 邮箱格式 | null 算通过 |
| `@Valid` | 级联校验对象里的对象 / 列表里的每个元素 | x01 的口味列表用到 |

**除了 @NotNull 一族，其他注解遇到 null 都算通过**，所以“必填 + 格式”要两个注解一起写。

### 分组校验（重点）

新增时不需要 id、需要密码；修改时需要 id、不需要密码。用分组区分：

- `@Validated(AddGroup.class)` 只检查 `groups` 里包含 `AddGroup` 的注解
- **没写 groups 的注解属于 Default 组，指定了分组时不会被检查！**
- 所以“新增修改都要检查”的注解要写 `groups = {AddGroup.class, EditGroup.class}` —— RuoYi-Vue-Plus 的 Bo 里就是这么写的

### 校验失败时抛的异常

| 场景 | 异常 | 怎么拿错误信息 |
|---|---|---|
| `@Validated` 校验 `@RequestBody` 或查询参数对象失败 | `MethodArgumentNotValidException`（是 `BindException` 的子类，所以处理 `BindException` 就能一起接住） | `e.getBindingResult().getAllErrors()` 每个的 `getDefaultMessage()` |
| 方法参数上的 `@Min` 等（类上有 @Validated） | `ConstraintViolationException` | `e.getConstraintViolations()` 每个的 `getMessage()` |

## 常见坑

1. 只写了 `@NotBlank` 没写 `@Validated` → 不校验，数据直接进来了。
2. 写了 `@Validated(AddGroup.class)`，注解却没写 groups → 不校验（分组坑）。
3. 想用 `@Validated` 却 import 成了别的包；`@Validated` 是 `org.springframework.validation.annotation.Validated`，
   约束注解都在 `jakarta.validation.constraints` 包里（Spring Boot 2 时代是 `javax.validation`，网上老教程要注意）。
4. 全局异常处理器里 `catch` 到异常之后不记日志，线上出了 bug 什么都查不到。
