## 事务

```sql
START TRANSACTION;
UPDATE account SET balance = balance - 100 WHERE id = 1;
UPDATE account SET balance = balance + 100 WHERE id = 2;
COMMIT;      -- 或者出错时 ROLLBACK;
```

ACID：**原子性**（全做或全不做）、**一致性**、**隔离性**（并发的事务互不干扰）、**持久性**（提交后不会丢）。
在 Spring 里写业务代码时，一个 `@Transactional` 就搞定了；m08 会用 JDBC 手写一遍，体会它帮你做了什么。

隔离级别、脏读 / 不可重复读 / 幻读是面试常考的概念，先知道名字，工作中遇到并发问题时再深入。

## 索引

```sql
CREATE INDEX idx_user_time ON orders (user_id, order_time);   -- 普通（联合）索引
CREATE UNIQUE INDEX uk_number ON orders (number);              -- 唯一索引
SHOW INDEX FROM orders;                                        -- 查看索引
DROP INDEX idx_user_time ON orders;                            -- 删除索引
EXPLAIN SELECT ...;                                            -- 查看执行计划
```

EXPLAIN 重点看：
- `type`：`const` / `eq_ref` / `ref` / `range` 都不错，`ALL` 表示全表扫描
- `possible_keys`：可能用到的索引；`key`：实际用的索引
- `rows`：预计扫描多少行

## 索引什么时候用不上

1. 联合索引不满足最左前缀（q03）
2. 对索引列用函数或做计算（q04）：`DATE(order_time) = ...`
3. `LIKE '%xx'` 以 % 开头
4. 类型不一致导致隐式转换：VARCHAR 列和数字比较
5. 数据量很小，MySQL 认为全表扫描更快（这不是问题）
