## 知识点速记

```
Throwable
├── Error                 （JVM 级错误，不用管）
└── Exception             受检异常：必须 try/catch 或 throws，例如 IOException
    └── RuntimeException  非受检异常：不强制处理，例如 NullPointerException、IllegalArgumentException
        └── ServiceException（我们自定义的业务异常）
```

```java
try (var conn = openConnection(); var stmt = conn.prepare()) {
    // 用完自动关闭：先关 stmt，再关 conn（与打开顺序相反）
} catch (SQLException e) {
    // 执行到这里时资源已经关闭了
    throw new ServiceException("数据库错误", 500, e);  // 转换异常时带上 cause
} finally {
    // 一定会执行
}
```

## 企业项目里的异常处理套路

1. Service 里发现业务问题 → `throw new ServiceException("用户名已存在")`
2. 不在 Controller 里 try/catch
3. 全局异常处理器 `@RestControllerAdvice` 统一捕获，转成 `R.fail(msg)` 返回给前端
4. 前端拿到 `{code: 500, msg: "用户名已存在"}` 弹个提示

第 9 章的 `GlobalExceptionHandler` 就模拟了第 3 步。

## 常见坑

1. `catch (Exception e) {}` 什么都不做 —— 吞掉异常是排查 bug 的噩梦，至少要打日志或重新抛出。
2. 包装异常时忘了传 cause，原始堆栈就丢了。
3. 不要用异常控制正常流程（比如用 try/catch 判断字符串是不是数字，在性能敏感处要避免）。
