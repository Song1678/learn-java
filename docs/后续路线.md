# 后续路线：从本项目到 RuoYi-Vue-Plus 和外卖项目

做完 ch01~ch09，你已经具备了“读懂框架代码”的 Java 基础。接下来按下面的顺序推进。
时间是按每天 3~4 小时估的，仅供参考。

```
阶段三-A  数据库与 Web 基础      MySQL → Spring Boot Web → MyBatis(-Plus)        约 2~3 周
阶段三-B  企业级常用组件          登录鉴权 → Redis → 其他常用技术                约 1~2 周
阶段三-C  上手 RuoYi-Vue-Plus     跑起来 → 读结构 → 代码生成 → 改一个功能         约 1~2 周
阶段三-D  完整项目               在 RuoYi-Vue-Plus 上做外卖业务模块              约 3~4 周
```

## 阶段三-A：数据库与 Web 基础

### 1. MySQL（约 1 周）

- 安装 MySQL 8 + 一个图形客户端（DataGrip / Navicat / DBeaver）
- 必须掌握：
  - 建库建表、常用类型（`bigint`、`varchar`、`decimal(10,2)`、`datetime`、`tinyint`）
  - 增删改查，`WHERE`、`ORDER BY`、`LIMIT`（分页）、`GROUP BY` + 聚合函数、`JOIN`
  - 主键、索引、唯一约束的作用
  - 事务的概念（要么全成功，要么全失败）
- 练习：把 ch09 的 `Category`、`Dish`、`ShoppingCart`、`Orders` 设计成表，手写 SQL 实现 `ReportService` 里的营业额统计和销量排行。

### 2. Spring Boot Web 入门（约 1 周）

先用一个**干净的 Spring Boot 3 项目**练手（[start.spring.io](https://start.spring.io) 生成，选 Java 17 + Spring Web），不要一上来就啃 RuoYi。

- `@RestController`、`@GetMapping/@PostMapping/@PutMapping/@DeleteMapping`
- 接收参数：`@PathVariable`、`@RequestParam`、`@RequestBody`
- `@Service`、`@Autowired` / 构造器注入 —— 对照你写过的 `MiniContainer`
- 统一返回 `R<T>`、全局异常处理 `@RestControllerAdvice` —— 对照 ch09 的 `GlobalExceptionHandler`
- 参数校验：`@Validated` + `@NotBlank` 等 —— 对照 ch05 的 `Validator`
- `application.yml` 配置
- 用 Apifox / Postman 调接口
- **练习**：把 ch09 的 `DishController` 改成真正的 HTTP 接口（数据先继续放在内存 Mapper 里）。

### 3. MyBatis / MyBatis-Plus（约 1 周）

- MyBatis：Mapper 接口 + 注解 SQL / XML SQL、`#{}` 参数、动态 SQL（`<if>`、`<where>`、`<foreach>`）、结果映射、驼峰映射
- MyBatis-Plus：`BaseMapper<T>`（对照 ch09 的 `BaseMapper`）、`LambdaQueryWrapper` 条件构造、分页插件、逻辑删除、自动填充 `createTime`
- **练习**：把上一步项目里的内存 Mapper 换成 MyBatis-Plus + MySQL，`Service` 代码基本不用动 —— 这就是分层的意义。

> 视频资源参考：B 站黑马程序员《JavaWeb 开发教程》（Spring Boot + MyBatis 部分）。苍穹外卖本身也是黑马的项目，配套视频可以对照着看业务设计。

## 阶段三-B：企业级常用组件

### 4. 登录与鉴权

- 概念：Session vs Token、JWT 的结构、拦截器 / 过滤器
- RuoYi-Vue-Plus 用的是 **Sa-Token**：`StpUtil.login(id)`、`@SaCheckLogin`、`@SaCheckPermission("system:user:list")`
- 理解 RBAC 权限模型：用户 - 角色 - 菜单（权限）

### 5. Redis

- 五种基本数据结构和使用场景（String / Hash / List / Set / ZSet）
- 缓存：查询先查缓存，没有再查库；修改时删缓存
- RuoYi-Vue-Plus 用 **Redisson** 封装为 `RedisUtils`，还用它做分布式锁、限流
- 外卖项目里：店铺营业状态、菜品缓存

### 6. 其他常见技术（用到再学）

| 技术 | 用途 | RuoYi-Vue-Plus 里 |
|---|---|---|
| Lombok | 自动生成 getter/setter/构造方法 | 全项目都在用（`@Data`） |
| Hutool | 工具类库 | 大量使用 |
| MapstructPlus | 对象转换（Entity ↔ Bo ↔ Vo） | `MapstructUtils.convert(...)`，对照 ch04 的 `BeanCopier` |
| EasyExcel | Excel 导入导出 | `@ExcelProperty`，对照 ch05 的 `CsvExporter` |
| 定时任务 | 订单超时取消等 | SnailJob（也可以先用 Spring 的 `@Scheduled`） |
| WebSocket | 来单提醒 | 有封装好的模块 |
| 对象存储 OSS | 上传菜品图片 | `ruoyi-common-oss`，支持 MinIO / 阿里云等 |
| Git | 团队协作 | 必须会：clone、branch、commit、pull、merge、解决冲突 |

## 阶段三-C：上手 RuoYi-Vue-Plus

### 7. 跑起来

1. 按官方文档准备环境：JDK 17、MySQL、Redis、Node.js（前端用）
2. 后端：导入 SQL 脚本 → 改 `application-dev.yml` 里的数据库和 Redis 连接 → 运行 `ruoyi-admin` 模块的启动类
3. 前端（plus-ui，Vue 3）：`npm install` → `npm run dev` → 登录后台

> 以公司实际使用的版本和文档为准，先问问同事用的是哪个分支 / 版本。

### 8. 读懂项目结构

```
ruoyi-admin          启动模块（main 方法、配置文件都在这）
ruoyi-common         各种公共能力，每个子模块一个功能：core、web、mybatis、redis、satoken、excel、oss ...
ruoyi-modules        业务模块：system（用户/角色/菜单/字典...）、generator（代码生成）、job、workflow ...
ruoyi-extend         监控等扩展服务
```

阅读建议：
1. 从一个简单的功能顺着读一遍：前端页面 → 请求 URL → `SysNoticeController` → `ISysNoticeService` → `SysNoticeMapper` → 数据库表 `sys_notice`
2. 对照你写过的东西：`R`、`ServiceException`、`BaseEntity`、`TableDataInfo`（分页）、`@ExcelProperty`
3. 用 IDEA 的 Debug 打断点跟一次请求

### 9. 用代码生成器做一个 CRUD

- 建一张表（比如 `takeout_category`）→ 后台“代码生成”导入表 → 生成代码 → 放到对应模块 → 执行菜单 SQL → 重启
- 读一遍生成的 Controller / Service / Mapper / Bo / Vo，你会发现和 ch09 的结构几乎一一对应

## 阶段三-D：外卖项目（建议做在 RuoYi-Vue-Plus 上）

既然公司用 RuoYi-Vue-Plus，最有价值的做法是：**在 RuoYi-Vue-Plus 里新建一个业务模块（例如 `ruoyi-modules/ruoyi-takeout`），实现苍穹外卖的业务**。
后台管理的登录、权限、用户、字典、文件上传、代码生成都现成，你把精力花在业务上。

### 功能拆分与建议顺序

| 顺序 | 功能 | 主要做法 | 你已经练过的 |
|---|---|---|---|
| 1 | 分类管理 | 代码生成 + 修改校验逻辑 | ch09 `CategoryService` |
| 2 | 菜品管理（含口味、图片上传） | 代码生成 + 一对多保存 + OSS | ch09 `DishService` |
| 3 | 套餐管理 | 多对多关系、起售校验 | ch09 扩展练习 2 |
| 4 | 店铺营业状态 | Redis | — |
| 5 | 用户端接口：菜品浏览 | 单独的 Controller，加缓存 | ch09 `listByCategory` |
| 6 | 购物车 | 按用户隔离 | ch09 `ShoppingCartService` |
| 7 | 地址簿 | 默认地址唯一 | ch09 扩展练习 3 |
| 8 | 下单 / 支付（模拟支付即可） | `@Transactional` 事务 | ch09 `OrderService` |
| 9 | 订单管理（接单、派送、完成、取消） | 状态机 | ch02 `OrderStatus` |
| 10 | 超时订单自动取消 | 定时任务 | ch08 `isPaymentTimeout` |
| 11 | 来单提醒 | WebSocket | — |
| 12 | 数据统计（营业额、用户、订单、Top10） | SQL 聚合 / Stream | ch08 Stream、ch09 `ReportService` |
| 13 | 报表导出 | Excel | ch05 `CsvExporter` |

用户端（小程序）可以先不做，用 Apifox 调用户端接口代替；有余力再用 uni-app 做一个简单前端。

### 做项目时的习惯

- 每个功能一个 Git 分支，做完合并
- 先设计表结构和接口（URL、参数、返回值），再写代码
- 写完一个接口立刻用 Apifox 测，别攒着
- 遇到问题先 Debug，再搜索，最后问人（问的时候带上报错信息和你的尝试）
